# TinyJobs

**TinyJobs** - асинхронная Python-библиотека для выполнения фоновых задач с сохранением состояния в базе данных и поддержкой повторных попыток.

Библиотека позволяет разбивать задачу на шаги, сохранять результаты выполненных шагов и не выполнять их повторно при восстановлении задачи после перезапуска приложения.

## Возможности

- Асинхронное выполнение задач через пул воркеров.
- Сохранение задач и их статусов в SQLite.
- Повторные попытки выполнения при ошибках.
- Разбиение задач на шаги с помощью `@ctx.step()`.
- Сохранение результатов шагов.
- Восстановление активных задач после перезапуска.
- Изоляция данных с помощью `namespace`.


## Быстрый старт

```python
import asyncio

from tinyjobs import JobManager, JobContext, JobStatus


async def my_task(ctx: JobContext) -> None:
    @ctx.step("get_users")
    async def get_users():
        return ["1", "2", "3"]

    @ctx.step("print_users")
    async def print_users(users):
        for user in users:
            print(user)

    users = await get_users()
    await print_users(users)


async def main():
    manager = JobManager()

    job_id = await manager.add(
        my_task,
        ctx_mode=True,
        retries=3,
    )

    while True:
        job = await manager.get(job_id)

        if job and job.status in (JobStatus.COMPLETED, JobStatus.FAILED):
            print(f"Задача {job.id} завершилась со статусом: {job.status}")
            break

        await asyncio.sleep(1)


asyncio.run(main())
```

`JobManager` запускает воркеры при создании, поэтому создавай его внутри асинхронной функции, где уже работает event loop.

В этом примере `retries=3` означает до трёх попыток выполнения задачи. Цикл ожидания нужен только для того, чтобы дождаться завершения задачи и посмотреть её статус. Если приложению необходимо продолжать работать, отдельный цикл ожидания может быть не нужен.

## Как работают шаги

Когда задача использует `JobContext`, её можно разделить на отдельные шаги:

```python
async def my_task(ctx: JobContext) -> None:
    @ctx.step("load_data")
    async def load_data():
        # Получение данных
        return {"items": [1, 2, 3]}

    @ctx.step("process_data")
    async def process_data(data):
        # Обработка данных
        return len(data["items"])

    data = await load_data()
    result = await process_data(data)

    print(result)
```

Каждый шаг получает уникальное имя в пределах задачи. TinyJobs сохраняет состояние и результат выполненного шага. При восстановлении задачи уже завершённые шаги могут быть пропущены, а их сохранённые результаты — использованы повторно.

Имена шагов следует сохранять стабильными: изменение имени шага может повлиять на распознавание ранее сохранённого состояния.

## Передача аргументов

Если задача не использует `JobContext`, можно передать аргументы через `async_function_kwargs`:

```python
async def send_notification(user_id: int, message: str) -> None:
    print(f"Пользователь {user_id}: {message}")


async def main():
    manager = JobManager()

    job_id = await manager.add(
        send_notification,
        async_function_kwargs={
            "user_id": 42,
            "message": "Задача выполнена",
        },
    )
```

При использовании `ctx_mode=True` TinyJobs передаёт объект контекста в задачу через аргумент `ctx`.

## JobManager

### Создание менеджера

```python
manager = JobManager(
    namespace="main",
    workers=10,
)
```

| Параметр | Описание |
|---|---|
| `namespace` | Пространство имён для хранения данных задач. По умолчанию — `"main"`. |
| `workers` | Количество воркеров, обрабатывающих задачи. По умолчанию — `10`. |

### Добавление задачи

```python
job_id = await manager.add(
    my_task,
    async_function_kwargs={},
    retries=3,
    ctx_mode=True,
)
```

Метод возвращает идентификатор созданной задачи.

| Параметр | Описание |
|---|---|
| `async_function` | Асинхронная функция задачи. |
| `async_function_kwargs` | Словарь аргументов, передаваемых функции. |
| `retries` | Максимальное количество попыток выполнения задачи. |
| `ctx_mode` | Если `True`, передаёт в функцию `JobContext`. |

### Получение задачи

```python
job = await manager.get(job_id)

if job is not None:
    print(job.status)
```

Метод возвращает объект задачи или `None`, если задача с таким идентификатором не найдена.

Основные статусы задач:

- `JobStatus.PENDING` — ожидает выполнения;
- `JobStatus.RUNNING` — выполняется;
- `JobStatus.COMPLETED` — завершена успешно;
- `JobStatus.FAILED` — завершилась ошибкой;
- `JobStatus.CANCELLED` — отменена.

## Восстановление после перезапуска

TinyJobs хранит состояние задач и шагов в базе данных. При повторном запуске менеджер загружает активные задачи и ставит их в очередь на выполнение.

Для восстановления функции задачи библиотека сохраняет путь к ней в формате `модуль:имя_функции`. Поэтому для надёжного восстановления после перезапуска используй функции, определённые на уровне модуля, а не вложенные функции или лямбда-выражения.

Восстановление состояния шагов помогает не выполнять повторно уже завершённые шаги. Однако оно не гарантирует exactly-once выполнение внешних побочных эффектов: например, если внешний запрос выполнился, но приложение завершилось до сохранения результата шага, запрос может потребоваться повторить. Для таких операций предусматривай идемпотентность.

## Пример использования

TinyJobs может подойти для фоновых задач, состоящих из нескольких этапов, например:

- загрузка и обработка данных;
- последовательное выполнение операций с сохранением промежуточных результатов;
- обработка заданий, которые должны переживать перезапуск приложения;
- повторные попытки при временных ошибках.

TinyJobs — небольшой проект, предназначенный для изучения и практического применения фонового выполнения задач в Python. Перед использованием в критически важных системах проверь, что поведение библиотеки соответствует требованиям твоего приложения.
